# Printer Operation

This guide covers what Printer Bot prints, the output modes, the dock's settings, printers and rules, how the dock saves, backing up your settings, what viewers can put on a receipt, how Printer Bot watches the print queue, how to style receipts with `theme.css` and where Printer Bot keeps its files. [Install](README.md#install) in the README comes first.

## What prints

Every event below has a trigger in the action. All triggers are on except channel point rewards. To stop printing an event, switch off its trigger in the action's trigger list.

| Platform | Receipts for |
|---|---|
| Twitch | cheers (bits), channel point rewards (off until you switch the trigger on), subscriptions and resubscriptions (a resubscription prints the total time subscribed, the current streak and the months paid in advance on a 3, 6 or 12 month plan, and a first-time subscriber shows the months paid in advance), gifted subs (a gift bomb prints one receipt that lists every recipient, however many there are), raids of 5 or more viewers (the Raid trigger's minimum, which you can change in the trigger list), Hype Trains (a receipt when a train starts, when the Bits Conductor or the Gift Sub Conductor changes, at each level up and when it ends) |
| YouTube | new members, member milestones, gifted memberships (the gifter's and each recipient's), Super Chats, Super Stickers. From 3.0.5 a Super Chat has the top of a Twitch cheer: the picture, the amount, "Name sent a Super Chat!" under it and the date, with only the viewer's message in the box (a Super Sticker the same, with "Name sent a Super Sticker!"). A YouTube receipt without a profile picture shows a grey placeholder |
| Kick | subscriptions, resubscriptions, gifted subscriptions (single and mass), raids, gifted Kicks (only gifts of type LEVEL_UP). Streamer.bot has to be logged in to Kick for any of these (see [Troubleshooting](TROUBLESHOOTING.md#nothing-from-kick-prints-even-a-test-from-streamerbot)) |
| StreamElements | tips |
| Streamlabs | donations |
| Fourthwall | donations, orders (with a total above zero, listing every item, 50 at most), memberships |

Kick raids and gifted Kicks arrive through two Streamer.bot *custom code event* triggers: `[Kick.bot] Raid` (event name `kickIncomingRaid`) and `[Kick.bot] Kicks gifted` (event name `kickKicksGifted`). They fire when a Kick integration or your own script in Streamer.bot raises those events. The **Streamer.bot Started** trigger warms up the receipt browser. Leave it on.

Each printed (or saved) receipt raises a Streamer.bot custom trigger called **Print Job Sent** (category SassyTP → Printer Bot) that other actions can react to.

**Hype Trains.** The four Hype Train triggers (Twitch → Hype Train: Start, Update, Level Up and End) are part of the import since 2.5.0. If your import is older, add them to the action by hand. **Advanced → Print Hype Trains** switches all four off, even when the triggers are in Streamer.bot. A train has two Conductors, as on Twitch: the top cheerer is the Bits Conductor and the top sub gifter is the Gift Sub Conductor. Each gets a receipt with the cap when they first appear and another when somebody takes the cap. The Level up receipt and the receipt at the end of the train list both. Streamer.bot's triggers send the level, the kind of train, the start time and the two top contributors. They send no total and no list of contributors, so Printer Bot keeps its own tally of the bits. While a train is on, each cheer it sees adds its bits to that cheerer, and Twitch's figure for the top cheerer raises that cheerer's number to Twitch's. The tally counts bits only and starts at the Start event. The figure of each Conductor always comes from Twitch. Twitch reports the Gift Sub Conductor's total in points and the receipts show gift subs: 500 points are one (a Tier 1 gift sub), so a Tier 3 gift sub counts as five. A cheer from before the train started, a Streamer.bot that was closed during the train or a missing Cheer trigger leaves those cheers out of the other numbers.

**When the End event does not come.** Twitch ends a train with an End event, and Streamer.bot passes it on. The Start, Update and Level up events carry the time the train expires. Twitch moves that time on each time the train reaches a new level, so Printer Bot keeps the latest one for every train id. When no End event has come by that time plus the wait of **Advanced → Hype Train end wait (seconds)**, Printer Bot prints the end receipt itself from the last event it saw. It carries the figures Printer Bot has and one more row, *Ended*, *time ran out*, and the Streamer.bot log says that the clock printed it. A real End that arrives afterwards prints nothing, because the receipt is out already. A train that speaks again after that was still going, and its tally continues. An event that carries no expiry time starts no timer. The times are kept in memory, so a restart of Streamer.bot or a program update forgets them, and the rule of the receipt page remains: a train that has been silent for 30 minutes stops counting cheers. Hype Train events reach Printer Bot only from Streamer.bot 1.0.4 or newer, because Twitch stopped sending the old Hype Train events in January 2026.

**Do not cut Hype Trains** (from 3.0). Every printer on **Thermal printer (ESC/POS)** output has a box, **Do not cut Hype Trains**, in its card. With it on, a Hype Train comes out of that printer as one strip of paper.

- **Where the train prints.** The four Hype Train triggers print on that printer as well as on the printers your rules choose. The box adds a printer and takes none away, so every other event prints where it did before, and the printer goes on printing them. To keep a Hype Train off the printer for everything else, add a rule for each of the four Hype Train triggers that sends it to the printer with the box.
- **What is not cut.** The first Hype Train receipt that prints begins the train, and the End ends it. In between, every receipt of that printer goes out without a cut and without the extra feed, whatever the event is. A cheer, a sub or a YouTube event that prints on the printer while the train runs comes out inside the strip. The dock says so under the box, and it is yours to move those events to other printers with rules or to leave them there and let them ride the train.
- **The cut at the end.** The End receipt is cut like any receipt, with the **Paper cut** of the printer. When the End prints nothing on a printer (a print that failed, or **Print Hype Trains** switched off during the train), Printer Bot sends one feed and one cut to every printer whose last receipt had no cut.
- **When the end is not seen.** The end receipt that Printer Bot prints by itself (see above) ends the train as well. A train that gets no Hype Train event for 4 hours is ended too. The button **Reset Hype Train**, under every printer that has the box, ends the train at once, cuts the open strips and brings the cuts back. The sentence next to it says whether a train runs, and shows what the last end or reset did for two minutes.
- **Where it does nothing.** A printer whose **Paper cut** is **None** has nothing to leave out and prints as before. The box shows only on thermal output. On the Windows printer driver or **Preview only** it is hidden, and the setting stays in the file for when the output changes.
- **Test prints.** The Start sample of **Test print** begins a train and the End sample ends it, like the real events. The end-to-end Hype Train test prints its six receipts as one strip, and the End is cut. The Hype Train state is in memory, so a restart of Streamer.bot forgets a train that was running, and the next receipt of the printer is cut as usual.

## Letter paper and print profiles

From 3.0 every printer has a **Paper size**: the rolls **80 mm** and **58 mm**, and **Letter (8.5 x 11 in)**, a sheet. Letter is for **Windows printer driver** output and for **Preview only**. A thermal printer has a roll and no sheets, so **Letter** is off in its list, and choosing **Thermal printer (ESC/POS)** for a printer on Letter takes it back to its roll. A settings file that says Letter for a thermal printer prints on the roll. **Auto-detect** looks for a receipt printer, so choose the printer of your sheets by name.

**How a Letter receipt is laid out.** The page of the receipt is 400 pixels wide and is printed 7.5 inches wide, which leaves half an inch of margin on a sheet 8.5 inches wide. A roll prints its 272 pixels (80 mm) or 181 pixels (58 mm) over 72 or 48 mm. A pixel of a Letter page is therefore about 1.8 times as large on paper as a pixel of an 80 mm receipt, and a line holds about half as much text again as a line of an 80 mm receipt. The picture is made at 300 dots to the inch, 2250 dots across. Lengths in the settings are lengths of paper: a High Roller message with a maximum length of 2 inches is 2 inches long on a roll and on Letter paper, and the built-in limit of 16.7 inches is 16.7 inches on both. From 3.0 a High Roller message on Letter paper also ends at the end of its page (see *What viewers can put on a receipt*).

**The Letter layout.** A printer on Letter paper has the row **Letter layout**, shown where the paper size Letter is possible (the Windows printer driver and Preview only). **Scaled like 80 mm** (the default) is the layout described above: the receipt of an 80 mm roll made larger to fill the page, with a big picture and a small box for the message. **Large message** gives the message the page. The viewer's picture is small, 2.3 inches across (the size it has on an 80 mm roll), in the top left corner, with the amount or the kind of event, the name of the viewer and the time beside it. The platform logo is at the bottom of the page, in the middle and half an inch tall. All the space between, the whole width of the page, is for the message and its pictures, or for the names of a gift list. A receipt with no picture starts its three lines at the left edge. From 3.0.5 the layout is for the receipts that earn a page: a cheer of at least the **Twitch High Roller threshold (bits)**, a Super Chat of at least the **YouTube High Roller threshold (amount)** (with or without a message), and gift subs and gifted memberships on Twitch, YouTube and Kick. The amount decides, not the switches **Allow Twitch High Roller prints** and **Allow YouTube High Roller prints**: a big cheer on a printer that does not allow High Roller prints gets the large page with its message as plain text. Every other receipt on that printer (a sub, a raid, a tip, a smaller cheer or Super Chat, a Super Sticker) prints **Scaled like 80 mm**. Every printer has its own layout, and printers that differ each draw their own receipt. A roll and a thermal printer have no such row: they keep the choice and do not use it.

**Image fit.** While **Large message** is chosen, the printer has one more row, **Image fit**, which says what a picture in a High Roller message does inside the space the words leave. **Fit** (the default since 3.0.1, it was Fill) scales the picture until all of it fits and keeps its proportions, so the space can have empty margins and nothing of the picture is cut off. **Fill** scales it until it covers all of the space and keeps its proportions, so what does not fit is cropped at the edges. **Stretch** scales it to exactly the size of the space, so nothing is cropped and there are no margins, but the picture can look squashed or stretched. With two or three pictures in a message they share the space equally. The row is hidden when the layout is not Large message, and it keeps its value.

**One page for a receipt.** On Letter paper a receipt takes one page, in both layouts. In the Large message layout the pictures of a message take what the words leave, down to three quarters of an inch each. In the other layout the pictures give back height first, down to three quarters of an inch each. What still does not fit is cut at the end of the page, and the Streamer.bot log says so (`Receipt from <name> cut to 2.3 in (it was 4.1 in), the end of the page of Letter paper`). Words in a very large font (a High Roller message in 300 pt) are cut before the pictures are. A receipt that has nothing to cut, such as a Hype Train receipt with its drawing, is printed smaller as a whole, down to 30 percent of its size at the least, so that all of it fits the page, and the log says by how much (`Receipt from <name> made 56 percent as large to be one page of Letter paper`). The one receipt that can take more than one page is a list of gifted subs with more than 100 names, described next.

**Gift lists on Letter paper.** The names on a gifted-subs receipt (Twitch and Kick) are set in columns, in the largest type that fits the page, from full size down to about 9 points, so that up to 100 names fit on one page. With more than 100 names the list goes on to the next page. In the **Large message** layout the first page holds 100 names, and every page after it holds as many as fit at the same type size and the same number of columns (3.0.2; the first page has the header, the pages after it have none, so they hold about 130 to 190 names, depending on the names, and are full), and the logo of the platform is at the bottom of every page, not only the last. In the **Scaled like 80 mm** layout every page holds 100 names at most and the logo is at the end of the last page, as before. Every page of a list has the same type size. At most 10 pages print in black and white and 5 in color (a page in color takes 20 MB of memory). A list with more names than the dock can lay out ends in a line that counts the rest (`...and 40 more`), and the log says when pages were left out. The items of an order are set in columns in the same way and kept to one page. How many names fit the first page depends on the layout. With **Large message** the picture is small and the logo sits at the bottom, so 100 names fit. With **Scaled like 80 mm** the big picture and the big logo take most of the page, so the first page holds only a few dozen names and the rest go on to the next page. Choose **Large message** for gift lists if you want them on as little paper as possible. An 80 mm or 58 mm roll prints the list in two columns when every name fits in half the width on one line (3.0.1), and in one column, as it always did, when one name does not.

**Pages.** A page is 10 inches. A receipt takes more than one page only when it is a gifted-subs list with more than 100 names. Each new page of such a list starts at the top of a page, so no line of text is cut in two, and the limits of 10 pages in black and white and 5 in color apply. The Streamer.bot log says so when pages are left out (at most once in 30 seconds). The log line of a Letter receipt says **Letter** or **Letter in color** after the output, for example `(2250x2424, windows, Letter in color, Office Laser, printer 2)`. The sheet has half an inch of margin. A printer whose unprintable edge is wider than half an inch prints the picture as wide as it can, and smaller when a page would not fit between its margins, so a page of Printer Bot is always one sheet.

**The print profile.** The row **Print profile** shows for a printer on Letter paper with the Windows printer driver, and for no other printer, because only that driver prints in color.

- **Black and white** (the default). The pictures on the receipt, which are the viewer's picture and the images of a message such as a cheermote or an emote, are shaded with the **Picture style** at the full 300 dots to the inch. **Detailed** is Floyd-Steinberg shading, which goes to the right on one row and to the left on the next, **Soft** is Atkinson shading and **Crisp** has no shading. The letters, the lines and the platform logo have no shading in any of the three, so they stay sharp. A message with more than 24 images is shaded as a whole. Printer Bot asks the driver for monochrome, so a printer with colored inks prints with black.
- **Color.** The receipt is printed as it looks, with no shading, as a picture of 24 bits to the pixel, and Printer Bot asks the driver for color. The row **Picture style** is not shown, because it would do nothing. The preview in the dock shows a note in place of a picture, because a color print has no black and white copy, and **Keep debug files** keeps no `last_receipt.png` for it.

**What Printer Bot asks the driver for.** Before a Letter print, Printer Bot asks the driver of the printer for its settings and sets the paper to Letter, the orientation to portrait and the color to color or to monochrome, through the standard Windows call for that (DocumentProperties). It sets only what the driver says it takes. A driver that does not let a program choose the paper is left as it is, and the receipt prints on the paper the driver has. The print goes out as one document. When the driver rejects a page, the document is discarded, and no half receipt comes out.

**Preview only.** A preview on Letter is a black and white picture 2250 dots across, shaded in the same way. The profile row is not shown for it.

## Printers that do not take ESC/POS

ESC/POS is a command language, and Windows has no flag that says a printer understands it. A printer that gets ESC/POS and does not understand it prints pages of strange characters, or keeps the job in its queue for good, and the receipts behind it wait. From 3.0 Printer Bot works against that in three ways. None of them sends anything to a printer by itself.

- **A warning.** Printer Bot reads what Windows says about the print queue of each printer, its driver and its port, and sends no data for that. A printer on **Thermal printer (ESC/POS)** output whose queue looks like an office printer, a home or office Epson, a multifunction device or a virtual printer that saves a file gets a warning under its printer list. The warning names the driver and the port and has two buttons: **Use the Windows printer driver** (one click, the same as choosing it under **Output**) and **Check this printer**. A queue named like a receipt printer shows no warning. The reading is a guess from words, so the warning offers and never blocks.
- **Check this printer.** The button sends one short line of text (`Printer Bot printer check`), four line feeds and a cut to the printer, only after you press it, and asks "Did the printer print ...?". The cut (from 3.0) is a full cut when the **Paper cut** of the printer is full and a partial cut otherwise, so the paper is easy to take. A printer without a cutter ignores it. Only you can tell whether it printed, because an office printer takes the job as well. Your answer is kept for that printer and its driver in `printer-checks.json` and replaces the guess. **Yes, it printed** removes the warning. **No** says that the printer does not take ESC/POS and offers **Use the Windows printer driver on Letter paper** (from 3.0). One click sets the output and the paper size together, because most printers that do not take ESC/POS are office or home printers, and 80 mm and 58 mm are rare for them. The answer **No** changes no setting by itself, since a thermal printer that is out of paper prints nothing as well. A printer gets one test line in 5 seconds. Your answer ends that wait, so **Check again** works at once after **Yes** or **No** (from 3.0). A click inside the wait is ignored, the button stays gray for the 5 seconds, and the Streamer.bot log says that the click was ignored. A line that could not be sent does not start the wait. A test line that is still in the print queue after 20 seconds, while the queue reports no problem, is taken out of the queue, and the check says so.
- **A hold on a stuck printer.** Printer Bot watches each job it sends to a print queue on this PC. When the first of its jobs in a queue is still there after two minutes (more for a very long receipt) and the queue reports no problem, or when the job has an error of its own for 15 seconds, Printer Bot holds the printer back. The next receipts for it fail at once, with the reason in the Streamer.bot log and in **Last print**, and the other printers go on. A queue that reports a problem (offline, out of paper, a jam) is not held back, because its receipts wait there and print when the printer is ready. The hold ends by itself when the job leaves the queue. The dock shows **Clear stuck jobs**, which takes out of the queue only the jobs Printer Bot sent and no other document, and **Try again**, which lets receipts go to the printer again and leaves the queue as it is. A paused job is yours to resume, and a job that Windows keeps after printing (the option *keep printed documents*) counts as gone.
- **Clear print queue** (from 3.0). Every printer with a print queue on this PC, on Thermal or Windows output, has the button **Clear print queue** in its card. It takes every job out of that queue, the documents of other programs as well, so it asks twice: the first click changes the label to "Delete every job in the queue? Click again" for 5 seconds, and the second click does it. Printer Bot reads the queue 200 jobs at a time, at most 1000 in one go, and says how many jobs it deleted, how many Windows refused and whether more are left. The sentence shows under the button for two minutes and is in the Streamer.bot log. It ends a hold as well, as **Try again** does. A queue on a network share is not opened, because that can take seconds, so it has no button, and neither has a printer on **Preview only**.

The jobs are watched by the job numbers that Windows gave them, and only in queues on this PC. A queue on a network share is not read, because that can take seconds. The watch is kept in memory. A restart of Streamer.bot or a program update forgets it, and a job that is still stuck holds the printer back again after the same wait.

The dock calls the receipt layout the "renderer".

**Without the dock.** Printer Bot works with the defaults above (Thermal printer output, Auto-detect, 80 mm). If Auto-detect does not find your printer, or you want another setting, edit `settings.json` in the data folder. In the dock's words:

- `mode` `escpos` is *Thermal printer (ESC/POS)*, `windows` is *Windows printer driver* and `png` is *Preview only*.
- `dither` `floyd` is *Detailed*, `atkinson` is *Soft* and `threshold` is *Crisp (no shading)*.
- `cut` is `partial`, `full` or `none`, `paperWidthMm` is 80 or 58 and `printer` is the exact Windows printer name.
- `paperSize` is `roll` (the width is `paperWidthMm`) or `letter`, `printProfile` is `bw` (black and white) or `color`, and `allowHighRoller` is `true` or `false` (from 3.0). Letter needs `mode` `windows` or `png`, and color needs `windows`. A value that is not on the list becomes the default. `letterLayout` is `scaled` or `message`, and `letterImageFit` is `fit` (the default), `fill` or `stretch`. Only a printer on Letter paper uses them, and `letterImageFit` only while `letterLayout` is `message`. A printer's line in the file leaves `fit` out and writes `fill` and `stretch`, so a printer that was left on Fill under 3.0.0 (no key in the file then) reads as Fit now: choose Fill again if you want it.
- `allowHostedUpdates` (`true` or `false`) is *Download updates (layouts and program updates)*. Write it as a plain `true` or `false` without quotes. The updater treats any other value as off.
- `autoUpdateCore` (`true` or `false`) is *Install updates automatically*. The default is `false`.
- `prereleaseUpdates` (`true` or `false`) is *Try prerelease versions*. The default is `false`. Write it as a plain `true` or `false` without quotes. The updater treats any other value as off.
- The other keys are `feedDots`, `highRollerBits`, `highRollerBitsPerInch`, `highRollerMaxInches`, `freePrintsPerMinute`, `hideLinks`, `ignoreTestTriggers`, `keepDebugFiles`, `hypeTrain` and `printersPerBrowser`.
- `printer`, `paperWidthMm`, `paperSize`, `mode`, `printProfile`, `dither`, `cut`, `feedDots` and `allowHighRoller` at the top of the file are printer 1. `extraPrinters` lists printers 2 to 100, each with the same keys. A printer in the list that has `paperSize`, `printProfile` and `allowHighRoller` at their defaults (a roll, black and white, allowed) does not write those three, so a file of older settings takes the same bytes as before. The key `routing` holds `routeAllElse` (the number of the printer for everything else) and `rules`. A rule looks like `{ "to": 3, "trigger": "TwitchCheer", "when": [ { "field": "bits", "op": "<=", "value": "500" } ] }`. The values of `op` are `=`, `!=`, `>`, `>=`, `<` and `<=` for numbers, `is`, `isnot`, `contains`, `notcontains`, `starts`, `ends`, `empty` and `notempty` for text, and `yes` and `no` for yes/no values. A rule that cannot be read is removed when the file loads, and the log names it. With no entry in `extraPrinters` the rules are not read. Printer Bot writes each printer and each rule on a line of its own, so a file with 100 printers and 300 rules of one test each takes about 47,000 bytes. Printer Bot does not let the file grow beyond 60,000 bytes (see *Limits* below).

`rendererUrl` holds where layout updates and program updates come from. Change it only as [Dock Selection](DOCK_SELECTION.md#how-updates-find-your-dock) describes. It must be the dock folder's full address ending with `/`, for example `https://dock.example.com/printer-bot/`. Otherwise the last part is taken for a file name and dropped. An unusable value is cleared, and the next dock that connects sets it again.

Close Streamer.bot before editing the file. Printer Bot reads it only at startup, and an edit made while it runs is lost if the dock saves a setting first.

**Auto-detect** guesses from printer names. In thermal (ESC/POS) mode it accepts only receipt-looking names (receipt, thermal, RONGTA, Epson TM, Star, Xprinter, POS), because raw printer commands sent to an office printer print pages of garbage. In the other modes it skips virtual printers (PDF, XPS, Fax, OneNote) and prefers a receipt-looking name. A printer you pick is used as long as it is installed, so pick a receipt printer.

The **Test** card is closed until you click its heading, and it stays open or closed as you left it. **Test print** offers twenty-three samples for Twitch, YouTube and Kick, and from 3.0.4 an entry for every other event Printer Bot prints (twenty-nine events in all, with StreamElements, Streamlabs and Fourthwall; see *Your own values* below). The list groups them by platform, in the order of the event list of a rule. **TwitchReSub** shows a resubscription with all three lines: 8 months in total, a streak of 5 months and 6 months paid in advance. **TwitchCheerLong** (60 lines, a lot of paper) is a 100-bit cheer, or as many bits as your High Roller threshold if that is higher, for trying out *bits per inch*. With the threshold at 0 it prints as plain text. **TwitchGiftBomb** lists 50 recipients, one to a line (about 40 cm of paper). **TwitchGiftBombBig** lists 500 (about 3 m of paper) and shows that a long list prints in full. It counts as ten of the 20 test prints a minute that the dock allows. Streamer.bot's own Test button sends sparse events, for example a gift bomb with no names and a YouTube member with no level name, so use these samples to see a full receipt. The Hype Train samples are the six receipts of a train (**TwitchHypeTrainStart**, **TwitchHypeTrainConductor** for the first Bits Conductor, **TwitchHypeTrainConductorSwitch** for a new Bits Conductor, **TwitchHypeTrainSubConductor** for the Gift Sub Conductor, **TwitchHypeTrainLevelUp**, **TwitchHypeTrainEnd**) and **TwitchHypeTrainEndToEnd**, which prints all six in a row. Hype Train samples keep their own tally and leave a running train alone. The Start sample shows the Normal, the Treasure and the Golden Kappa train in turn, and the other steps use the kind it showed last.

**Your own values (3.0.4).** Under the list, the dock shows the values of the chosen event as Streamer.bot sends them: first the ones the receipt prints (the name, the amount with two digits after the point, the currency, the message, the names of a gift list one to a line, the items of an order such as `2 x Shirt` ...), then **More values**, closed, with every other value Streamer.bot sends with that event and that a routing rule can test, and **Other values** for a name of your own. Change any of them and press **Test print**: Printer Bot prints that event with your values through everything a real event of its kind goes through (your rules with **Follow the rules**, High Roller and YouTube High Roller with your bits or your amount and currency, the exchange rates), and **the receipt says TEST at its bottom**, so a receipt made from typed values can never pass for a real one. A sample whose values you did not change prints as the sample, without that line. An empty box is not sent. A value with a fixed set, such as the tier of a sub, the role of a viewer or the kind of Hype Train, is a list to pick from: **(not sent)** and exactly the values Streamer.bot sends (Prime, Tier 1, Tier 2 and Tier 3 for a sub; a gift sub has no Prime). The dock keeps what you typed for each event in this browser until you press **Reset to the sample** (**Reset to the defaults** for an event that has no sample). Printer Bot takes at most 600 values, a text of at most 4,000 characters and a number of at most 10^15, and refuses a name that steers Printer Bot itself (such as `printers` or `isTest`) and a picture address; the dock marks such a value first and sends nothing. A list of more than 100 names or items counts as ten of the 20 test prints a minute. This is the way to try a YouTube Super Chat, a membership, a Kick event or a donation with the values you want: Streamer.bot's own test of those events sends data you cannot change.

## Printers and rules

Printer Bot prints on one printer until you add another. **Add another printer** (in Settings, under the rows of printer 1) makes a card for printer 2, and the dock adds printers up to 100. Printer 1 keeps the settings it always had, and its rows move into its card. Every printer has its own **Printer**, **Paper size**, **Output**, **Print profile** (for Letter paper on the Windows printer driver), **Picture style**, **Paper cut** and **Extra feed before cut** (the last two for the thermal output) under *Paper and output*, and its own switches **Allow Twitch High Roller prints** and **Allow YouTube High Roller prints** under that. A new printer starts with a copy of the settings of printer 1 and no printer chosen (except **Allow YouTube High Roller prints**, which starts off on every new printer), and takes no receipts until you choose one. A printer whose output is *Preview only* needs none, because it saves a picture and has nothing to send to. Only printer 1 can use Auto-detect. Printers 2 and up are chosen by name, and a printer that one card uses cannot be chosen on another. A printer that was removed from Windows is not replaced by another one. Its receipts fail, the log and the dock say so, and the other printers go on.

**Which printer prints what.** Each card has a list of rules under **Prints these events**. A rule has:

- **A trigger.** One kind of event, such as *Twitch: Cheer* or *YouTube: Super Chat*, or a family such as *Any Twitch event*. The list holds every kind of event that Printer Bot prints (29, counting the two Kick helpers).
- **Tests, if you want them.** Each test compares one parameter that Streamer.bot sends with that trigger to a value. The parameters are the variables Streamer.bot lists for the trigger, for example **Bits** for a cheer, **Tier** for a subscription and **Viewers in the raid** for a raid. **Other parameter...** takes the name of any variable. A family has no tests. From 3.0.9 the **Amount** of a YouTube Super Chat or Super Sticker is tested in your **YouTube currency**, converted like YouTube High Roller, so a test of 20 with U.S. dollars means 20 dollars whatever currency the viewer paid in; an amount in a currency with no exchange rate passes no such test. Every other parameter is tested as Streamer.bot sends it.

A rule passes when the event is of its trigger and all of its tests pass. A printer prints an event when the event passes at least one of its rules. So several rules on one card mean "or", and the tests inside one rule mean "and". An event that passes rules on two printers prints on both of them, one receipt each. One printer takes an event that passes no rule at all. Turn on the switch **Use this printer for everything else** at the foot of its card, or choose the printer in the list **Everything else prints on** under the cards. Both show the same pick, and one printer has it at a time: turning the switch on for a printer turns it off for the one that had it. The switch that is on cannot be turned off, so turn another one on to move it. It is printer 1 until you pick another. A printer that is not set up cannot be picked. If the printer you picked loses its setup, the pick stays, the dock says so on the card and under the list, and everything else prints on printer 1 until you choose a printer for it.

For example, with printers 1 and 3: the rule *Twitch: Cheer where Bits is greater than 500* on printer 1 and *Twitch: Cheer where Bits is less than or equal to 500* on printer 3. A cheer of 600 bits prints on printer 1, a cheer of 500 bits prints on printer 3, and a raid, which no rule names, prints on printer 1 because it is the printer for everything else.

| Kind of parameter | The tests |
|---|---|
| number | equals (=), does not equal (≠), is greater than (>), greater than or equal to (≥), is less than (<), less than or equal to (≤) |
| text | is, is not, contains, does not contain, starts with, ends with, is empty, is not empty (capitals do not matter) |
| yes or no | is yes, is no |

A number that Streamer.bot sends as text still counts as a number. A parameter that is missing from an event, or that cannot be read, fails every number test. A text test reads it as empty text, and a yes/no test reads it as no. A test that needs a value passes nothing until it has one. Amounts of money are compared as numbers in the currency the service sends, with no conversion. The amount of a YouTube Super Chat is typed in whole units (20 for 20 dollars), and Printer Bot compares it with the amount Streamer.bot sends in millionths.

**While you edit.** A rule is saved when it is complete. A new rule has no trigger and is saved when you pick one (from then on it prints every event of that trigger, until you add tests). A rule that you change keeps its last complete version in force until the change is complete, and the line under the rule says what is missing. Removing a printer removes its rules, and the printers after it move up one number. Removing the last extra printer returns to one printer and removes the rules.

**Many printers.** With up to five extra printers the cards are open, as they are with one or two printers. With more, every card starts closed (printer 1 as well) and is one line: **Printer 12**, the name of the printer (or **Not set up yet**, or **Preview only**), the paper width, the output and how many rules send to it, for example `58 mm · Thermal · 2 rules`. Click the title of a card to open or close it. Every card closes, the card of printer 1 included (from 3.0), and a closed card of printer 1 shows its paper, output and rules like the others. The dock builds the content of a card when you open it first, and it remembers in this browser which cards you opened (by printer number). **Remove** is in the open card only. A printer with no printer chosen, a printer that Windows does not have, and a printer whose print queue has a problem each show **Needs attention** in their line, and above the list the dock counts them (for example "3 printers need attention"). **Expand all** opens every card, **Collapse all** closes them, and **Find a printer** shows only the card whose number you type (for example 12) and the cards whose name holds what you type. The lists that name printers (**Everything else prints on** and **Print on** in the Test card) show each printer as number and name, for example `12: Receipt B`, and a printer that is not set up reads `12: not set up` and cannot be chosen. **Add another printer** is switched off at 100 printers and says "Printer Bot takes up to 100 printers. Remove one to add another." **Add a rule** is switched off at 300 rules.

**Limits.** 100 printers, 300 rules in all, four tests in a rule and 48 characters in a value. The settings file may take up to 60,000 bytes. 100 printers with ordinary names and 300 rules of one test each take about 47,000 bytes. The limit exists because the part of Printer Bot that reads your update switches reads at most 65,536 bytes of `settings.json` and ignores a larger file, which would turn a switch you set to off back to its default. A save that would take the file over 60,000 bytes is refused as a whole. Your earlier settings stay, the Streamer.bot log has one line (`Could not save settings: they are too large, they would take 71,340 bytes and the limit is 60,000 ...`), and the dock shows the reason in a warning line above the printers. Remove rules or printers, or shorten their names, and save again. A quiet line, **Settings use X of Y bytes.**, shows in Settings when the file is above 70 percent of the limit. A file that is already over the limit (made by hand) can be brought down, because a save that makes it smaller goes through. A printer after the 100th, and a rule after the 300th, are left out when Printer Bot reads or restores settings, and the log says so.

**Checking a rule.** **Test print** has a row **Print on** with each printer and **All printers**. Under it, **Follow the rules** (shown with two printers or more) sends the sample where your rules send an event of its kind, tested with the values the sample carries (or, from 3.0.4, the values you typed under the list): the Cheer sample has 100 bits, the Raid sample 42 viewers, the Super Chat sample $5.00, and a Twitch sub sample is a Prime sub. **Print on** is grey while the switch is on. A sample that no rule names goes to the printer for everything else, and the log says where it went in the line a real event gets. The end-to-end Hype Train test sends each of its six receipts where the rules send that kind of Hype Train event. The test takes one of the 20 places of the minute for every printer the rules choose. The dock keeps the switch in this browser and starts with it off. With many printers the list holds every printer by number and name, and **All printers** is its last entry (printer 1 is chosen at first, so a test does not print a hundred receipts by accident). **Check where an event prints** (in Settings, under the cards) takes a trigger and the values you type for the parameters that your rules test. It says which printers such an event would print on and which rules it passes. When an event prints on more than ten printers, the answer names the first ten and says how many more there are. The same goes for the rules it passes. It prints nothing. The Streamer.bot log also says where each event goes, in a line such as `TwitchCheer goes to printer 1 (rule 2).` Behind the dock's list, a test print takes its printers as the text `all`, a number, numbers separated by commas, or ranges such as `2,5,10-12`. A number that is no printer, or a printer that is not set up, is left out and the log says which. When none of the printers a test print names can take a receipt, nothing is printed, the log says why and the last print in the dock shows the same words.

**Paper.** Every printer prints a receipt of its own, drawn for its paper (a roll of 80 or 58 mm, or Letter). An event that prints on three printers counts three times toward **Free receipts per minute** (when it is a free event), and a test print on three printers counts three times toward the 20 test prints a minute. A test print on more than 20 printers takes all 20 places of the minute, so it prints once a minute. The two long samples take more places for each printer (ten for **TwitchGiftBombBig**, six for **TwitchHypeTrainEndToEnd**), so they print on two and three printers at most. In *Preview only* mode the pictures of printers 2 and up end in `_p2`, `_p3` and so on.

**Many printers in the log.** When an event prints on more than 10 printers, the log has one line for the route (`TwitchCheer goes to 100 printers: 1 to 100 (rule 1 to 300).`) and one summary line for the receipts. A printer gets a line of its own only when it fails (the first 10, then a count of the rest), and the last print in the dock names the first reasons. Print queues and printer names add a few lines: one count line for queues that look healthy, and up to 10 lines each for queues in trouble and for notes about printer names, with a count of the rest. The summary line has the same parts as the line of one receipt, added up over the printers, for example `TwitchCheer | Wait: 0 ms | Render: 61 ms (session 15, layout 5, shot 41) | Raster: 2 ms | Save: 167 ms | Other: 93 ms | TOTAL: 323 ms (576x523, png, 100 printers)`. Printers with the same paper and picture style share one decoded and dithered picture. A High Roller cheer is drawn twice when some printers allow High Roller and some do not (once each way), and no other event is.

**Receipt browsers.** Printer Bot draws each receipt in a hidden Edge browser. **Printers per browser** (in Settings, under **Everything else prints on**, with two printers or more) says how many printers one browser serves. Printers 1 up to that number use the first browser, the next group uses the second browser, and so on. With 3 per browser, 9 printers use 3 browsers and 10 printers use 4. The line under the setting says it for your printers, for example "9 printers at 3 per browser use 3 browsers.", and counts the browsers that run. The extra browsers start in the background, one a second after the other, when you save the setting or add printers, and they close when the setting or the printers need fewer. The default is 100, which keeps every printer in one browser, as every version before 3.0 did. Printer Bot never starts more than 16 browsers. With 1 printer per browser and more than 16 printers, printer 17 uses the first browser again, and so on.

The value is a whole number from 1 to 100. The dock refuses 0, a negative number, a fraction, an exponent such as 1e2, text and an empty box. It shows "Enter a whole number from 1 to 100. Printers per browser stays at 3." under the setting, puts the number in use back into the box and saves nothing. The keys **-**, **+**, **.**, **,** and **e** do nothing in the box. Printer Bot checks the number itself as well. A value that arrives from a backup file or from another program is refused in the same way, and a whole number outside 1 to 100 in `settings.json` becomes 100.

An event for printers of more than one browser is drawn by each of those browsers at the same time, at most four at once, and every printer gets its picture. More browsers use more memory. Hype Train receipts, and the dock's Hype Train test prints, are always drawn by the first browser, because the page of a browser keeps the running tally of the train. Like the first browser, the others keep running when Streamer.bot closes, and the next start reuses the ones it needs and closes the rest. A browser that cannot start, for example because another program listens on its port, fails only its own printers (see *Troubleshooting*).

## How the dock saves

The dock saves a change a moment after you make it and shows **Saved ✓** when Printer Bot reports the new value in its next status. If the connection to Streamer.bot is lost first, the dock keeps the change and sends it as soon as the connection is back. While a change waits, the line **Not saved yet. Waiting for Streamer.bot.** shows. If Streamer.bot receives a change and does not answer with a status that holds the value, the field goes back to the value Printer Bot reports after four seconds, and no Saved mark shows. If a save is refused while the connection is up, the dock tries again after 1, 2, 4, 8 and 16 seconds, and then says "The change could not be saved. The settings show what Printer Bot has." A **Test print** carries every change that has not been saved yet, so a test never prints with a setting the dock does not show.

## Backing up your settings

Printer Bot keeps your settings in `settings.json` in its data folder (see [Where Printer Bot keeps its files](#where-printer-bot-keeps-its-files)). If Streamer.bot loses that folder, or you set Printer Bot up on a new PC, the printers and rules would be gone with it. Two things bring them back. Printer Bot keeps a copy by itself on the same PC (the first bullet). The **Backup** card of the dock saves them to a file with one click, from 3.0.0-beta.1, and that file also moves your setup to a new PC.

- **The automatic copy.** Printer Bot also keeps a copy of `settings.json` and of `theme.css` by itself, in `%LOCALAPPDATA%\SassyTP\printer-bot\mirror\`. That folder is outside the Streamer.bot folder, so it survives a new Streamer.bot folder, an import into a fresh installation and a crash that wipes the folder, as long as you stay on the same PC and the same Windows account. A new PC starts without a copy. The copy is written about two seconds after you change a setting, and once when Printer Bot starts if it differs from the file. When Printer Bot starts and `settings.json` is missing, empty or cannot be read, it puts the copy back, with `theme.css` if that is missing too. A file that exists but cannot be used is kept as `settings.json.bad` first. A `settings.json` that can be read is never replaced. The log has one line (`Restored your settings from the backup copy ...`) and the dock says that the settings were restored from the backup copy. The folder also holds `mirror.txt`, which says when the copy was written, by which version and for which data folder. Every Streamer.bot folder of your Windows account shares this one copy. If you run two (a test copy beside the real one, for example), the one that saved last wrote it, and the log line of a restore names the folder it was written for (`written for the folder Streamer.bot-x64-1.0.7`). To start from nothing on purpose, delete `settings.json` and the folder `mirror` together.
- **Save settings.** One click has Printer Bot write a file named like `printer-bot-settings-2026-10-14-153012.json` (the date and the time of the save) into the folder `backups` of its data folder, `SassyTP\printer-bot\backups` in your Streamer.bot folder, and the dock shows the name of the file. This works in an OBS dock too: up to 3.0.2 the file was a download of the browser, which an OBS dock drops without a word. Copy the file somewhere safe, with your other backups, because that folder is lost with the Streamer.bot folder. Printer Bot never writes over a file there, and it keeps at most 200 of them: when the dock says the folder is full, delete old ones. The file is plain text. It holds your printers, your routing rules and the print options: paper width, output, picture style, paper cut, extra feed, Twitch and YouTube High Roller, image sites, free receipts per minute, links, Hype Trains, test triggers and debug files. It holds no password and no web address. With a Printer Bot older than 3.0.3 the dock still makes a download of the browser.
- **Restore settings.** Click it and choose a file made by **Save settings** (from 3.0.3 they are in `SassyTP\printer-bot\backups` in your Streamer.bot folder). The dock shows what the file holds: when it was saved, by which version, how many printers and routing rules. Nothing changes until you press **Restore these settings**. Printer Bot then replaces those settings, and the dock says "Settings restored." Printer Bot limits some numbers and it removes a rule that names a printer your setup does not have. If it kept a different value for something, the dock lists what differs ("Printer Bot kept other values for: extraPrinters, routing.") and gives the reason that Printer Bot reports, for example that the settings would take more bytes than the limit (see *Limits*). A file with settings that are larger than Printer Bot accepts is refused before anything changes.
- **The update switches are not in the file.** **Download updates**, **Install updates automatically** and **Try prerelease versions** stay as you set them in the Updates card. Restoring a file never changes them, so a file from another person cannot start a download or an install.
- **When the dock cannot open files.** Some OBS docks cannot open a file (and, with a Printer Bot older than 3.0.3, cannot save one). Open **Settings as text** in the Backup card. **Show settings as text** and **Copy the text** give you the same content as text that you can keep in a note. To restore, paste the text into the box, press **Check the pasted text** and then **Restore these settings**.

After a restore on a new PC, look at the printer names. A file made on another PC names the printers that PC had, and the dock marks a printer that is not installed here.

## What viewers can put on a receipt

- Normal messages print as plain text, with no pictures. A message that holds HTML prints the words of it and not its tags (3.0.1: before, `<img src=` and `</a><span style=...` came out on the paper): an `<img>` tag is dropped with its address, the tags that break a line break it, a script or a style is dropped with what is inside it, and entities such as `&amp;` are decoded. Nothing of it styles anything, and a message with no tag in it is printed as it is. A link in it stays text, or reads `[link]` when **Hide links in messages** is on, a link to a picture on an image site too: only a High Roller message has pictures (see *Images in messages*). They are cut at 500 characters and are not moderated. Twitch AutoMod and Streamer.bot's own filters are the only filters.
- A cheer of at least the **Twitch High Roller threshold (bits)** threshold may style its message with HTML: bold, colours, sizes, rotated text, text that stays on one line (`white-space: nowrap`), tables, and Twitch, Kick, BTTV, 7TV and FFZ emotes. Printer Bot removes these from every message, High Roller or not: clickable links, scripts, event handlers, forms, frames, `<style>`, `<link>`, `<meta>`, SVG, CSS that loads anything, and images from any other site than the emote hosts and the image sites you switched on. A web address typed as plain text still prints as text. Allowed HTML can still look ugly or obnoxious, so set the threshold as high as you are comfortable with. From 3.0.4 the cheermotes of a cheer (`Cheer100`, `Kappa50` and the other words that pay its bits) are left out of its message, styled or not: the title shows the bits, and a picture that opens the message stays first, as in a test from Streamer.bot, which sends the message without them. A word that only looks like one (`Cheer` with no number, `Win10`) stays. A printer with **Allow Twitch High Roller prints** off prints such a cheer as a cheer below the threshold prints: plain text, and none of the limits below apply to it.
- A High Roller message is cut at 4000 characters of HTML and 400 elements or pieces of text. Its pictures are limited to 64 pixels (about 17 mm). A receipt with a viewer's message in it stays under about 1.3 m of paper. Gift sub lists have no limit, because one receipt lists every recipient, and neither has the item list of a Fourthwall order (50 items at most), because every paid item has to print. Names are cleaned of invisible and text-direction characters and cut at 48 characters. A name or word that is wider than the line is broken where the line ends, so a long name keeps its ending on the paper.
- *Bits per inch* limits a High Roller message to *bits ÷ this number* inches of paper, on Letter as on a roll. At `10`, a 100-bit cheer gets up to 10 inches and a 25-bit cheer up to 2.5 (decimals such as `2.5` work, and `0` means no limit of its own). Longer messages fade out at the limit, and the Streamer.bot log notes how much was cut. Avatars, names, logos, dates and normal messages have no limit. With no *maximum length* (next bullet), a message prints at most about 16.7 inches, whatever the setting.
- *Maximum length* sets the final limit on a High Roller message. It prints at most this many inches (up to 40), whatever *bits per inch* (or *amount per inch*) says. Setting it also replaces the built-in 16.7 inch limit, so `30` allows messages up to 30 inches. It applies to High Roller messages only (cheers, and Super Chats from 3.0.2) and leaves gift sub lists and every other receipt at full length.
- **YouTube High Roller** (3.0.2). A Super Chat with a message, of at least the **YouTube High Roller threshold (amount)** in the **YouTube currency**, prints its message styled under the same rules as a High Roller cheer (the HTML that is allowed, what is removed, the limits above, pictures from image sites), on each printer that has **Allow YouTube High Roller prints** on. That switch is off on every printer until you switch it on, so nothing changes for anyone who does not. *Amount per inch* limits such a message to *amount ÷ this number* inches of paper, as *bits per inch* does for a cheer: at `2.50`, a Super Chat of 10.00 gets up to 4 inches. A Super Chat comes in the viewer's own currency. One in your currency is compared as it is. One in another currency is converted with the exchange rates of the U.S. Treasury (*Treasury Reporting Rates of Exchange*, published every quarter), which Printer Bot loads in the background while a printer has the switch on, at most every 12 hours, and keeps in `exchange-rates.json` in its data folder. When it cannot load them and has none from the last six months, only Super Chats in your currency can print as YouTube High Roller messages, and the dock says that currency exchange is offline. A Super Chat with no message, a Super Sticker and every other YouTube event print as before. Streamer.bot's *Simulate* cannot set the message or the amount of a Super Chat, so the dock's **Test print** of **YouTubeSuperChat** (5.00 U.S. dollars, *Great stream!*) is the way to see one before a real one comes. It prints as a YouTube High Roller message when 5.00 U.S. dollars reach your **YouTube High Roller threshold (amount)**, so set the amount to 5.00 or less for the test (with another currency than U.S. dollars, the exchange rates must have loaded).
- From 3.0.0-beta.6, a High Roller message on **Letter paper** is limited to one page as well, whatever *bits per inch* and *maximum length* allow, because a sheet has an end. The message gets what the viewer's picture, the name and the footer leave of the page, at least 1 inch, and a longer message fades out there. A picture of the viewer takes about 4 inches of the 10, so a message on a receipt with a picture has about 2 inches. The Streamer.bot log says `the end of the page of Letter paper`. A shorter *maximum length* or *bits per inch* limit still applies and is the one the log names. A roll prints a continuous strip and keeps the limits above.
- A Fourthwall order or donation that arrives without a user name, or with one that shows as nothing (only joiners, combining marks or blank Braille characters), prints **Anonymous supporter**. The buyer's e-mail address is never shown.

When something that matters is removed from a message, the Streamer.bot log says who sent it.

## Images in messages

From 3.0 a message can print a picture. Since 3.0.1 that is only a High Roller message, the one kind of message that styles its words: a message that is not printed as a High Roller message has no pictures and no styling, whatever you switched on. That is a cheer under the Twitch High Roller threshold, a cheer on a printer with **Allow Twitch High Roller prints** off, a Super Chat that is not printed as a YouTube High Roller message, and every other kind of message (a subscription, a gift, a donation, a reward and so on). Its words are printed, and a link in it is text. You choose the sites Printer Bot may load pictures from in the dock, in the **Advanced** card, under **Images in messages**: one box for each site (Imgur, Catbox and ImgBB at first). **Every site is off until you switch it on.**

- **Which links print as a picture.** Only a direct link to a picture on a site you switched on: `https`, the site's own host name and a path of the shape that site uses, ending in `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp`. That is `https://i.imgur.com/<name>.png` (Imgur), `https://files.catbox.moe/<name>.png` (Catbox) and `https://i.ibb.co/<id>/<name>.png` (the "direct link" that ImgBB shows). A page of ImgBB (`ibb.co/<id>`), a video or `.gifv`, an SVG, a link with a port or a user name or without `https`, and every link to a site that is off stay text. A query or fragment after the address is dropped.
- **Imgur links people copy from the site (3.0.11).** The page of one picture prints that picture: `https://imgur.com/<name>`, with or without an ending such as `.jpg`, also with `www.` or `m.` in front, and `https://i.imgur.com/<name>` without an ending. An album (Imgur calls it a post) prints **its first picture only**, never the rest: `https://imgur.com/a/<id>`, `https://imgur.com/a/<title>-<id>`, `https://imgur.com/gallery/<id>`, `https://imgur.com/a/<id>.jpg` and the same with `www.`, `m.` or `i.` in front. The link of an album does not say which picture comes first, so before the receipt prints, Printer Bot asks imgur.com for the album's list of pictures (or, if that gives no answer, the album's preview picture) and prints that one picture from `i.imgur.com`. This takes at most 3 seconds for a message. An album Imgur gives no picture for prints `[image]`, and an album whose first item is a video stays text. Any other page of Imgur (a user, a tag, the upload page) stays text. The lookup is only made for a message that can print pictures: Imgur switched on, and a High Roller message on a printer with **Allow images** on.
- **How it prints.** The link is replaced by the picture on a line of its own in the words of the message, centered, as wide as the paper at most and 4 inches of paper tall at most, with its proportions kept. In the **Large message** layout of Letter paper the picture instead takes the space the words leave, as **Image fit** says. A GIF prints as a still. A message prints at most three pictures, and a fourth link stays text. On a thermal printer the picture is shaded like a viewer's profile picture, and on Letter paper it follows the printer's print profile.
- **When it does not load.** A picture that does not come within about 2.5 seconds, is missing, is not a picture or has more than 33 million pixels prints as `[image]` where it would have been, and the receipt is not held up. The same address is not tried again for ten minutes.
- **Each printer.** Under every printer there is a switch, **Allow images** (on by default, shown while a site is on). A printer with it off prints a picture link as text while the other printers print the picture, so a printer that stays in view of the audience can stay without pictures. The switch has nothing to do for a printer with both **Allow Twitch High Roller prints** and **Allow YouTube High Roller prints** off, which has no pictures at all. The sites you switched on are one list for all printers.
- **Hide links in messages.** A picture in a High Roller message shows even when **Hide links in messages** is on, because that switch is for the messages that are not High Roller messages. There every link reads `[link]`, a link to a picture on a site that is on too.
- **High Roller.** A cheer at or above the threshold, on a printer with **Allow Twitch High Roller prints** on, is markup (and so is a YouTube High Roller Super Chat on a printer with **Allow YouTube High Roller prints** on), and a picture works in it in two ways while the site is on. A link typed in the text becomes a picture where it was, and the styling around it stays. An `<img>` tag whose `src` is such a link is one picture of at most 64 pixels (like every picture in a High Roller message) on a roll and in the *Scaled like 80 mm* layout. In the **Large message** layout the pictures of both kinds are taken out of the styled text and set after it, as **Image fit** says. Together they are at most three. A cheer below the threshold, or on a printer with **Allow Twitch High Roller prints** off, is never markup and has no picture (nor is a Super Chat that is not printed as a YouTube High Roller message): its words are printed and its tags are not, and a link in it is text, an `<img>` tag is dropped with its address. In the **Large message** layout a High Roller message that starts with its picture prints the picture first, and one that has words before its picture prints the picture after the words.
- **What to think about.** Printer Bot does not look at the picture, and nobody else checks it: anyone whose cheer reaches the Twitch High Roller threshold, or whose Super Chat reaches the YouTube High Roller threshold on a printer that allows it, can make this printer print a picture from a site you switched on. The site sees your PC's internet address when it serves the picture (Printer Bot sends no cookie, no login and no referrer), and a picture costs paper, up to 4 inches each. Switch on only the sites you accept that from, and switch **Allow images** off on a printer that should never print one. Printer Bot keeps nothing of a picture: the hidden browser's cache is emptied at the quiet gap after a receipt that held one. See [Privacy](PRIVACY.md#privacy-and-third-party-services) and [Security](SECURITY.md), and [Troubleshooting](TROUBLESHOOTING.md#a-link-to-a-picture-prints-as-text-as-link-or-as-image) when a link does not print as a picture.

## Keeping an eye on the printer

Before each receipt, the action asks Windows whether the print queue can print and whether jobs are stuck. The dock's **Print queue** row shows the answer, and the Streamer.bot log reports it once per change when the queue shows an error or stuck jobs.

A printer that is off or unplugged prints an accepted job when it comes back. Windows reports what the driver tells it, and some drivers cannot report that the paper has run out. With up to five printers the dock's status card has a row for each printer. With more it has one row, **Printers**, such as "100 printers, 3 cannot print", and a closed list **Show the 3 printers that cannot print** with one line for each of them. The status line names the first printer that cannot print and counts the others ("2 more printers cannot print either."). The **Last print** row names up to five printers and then says "and N more", for example "printers 1, 2, 3, 4, 5 and 95 more". Printer Bot keeps each print queue reading for 5 seconds (60 seconds for a queue that took 400 ms to answer), so a long list of printers does not slow the status down.

If no printer can be found or opened, or the spooler is not running, the receipt is logged as "Print failed" and shown in the dock. Printer Bot does not retry it.

If the printer you chose for printer 1 was removed or renamed, Printer Bot warns in the Streamer.bot log and the dock's **Note** row, then prints on whichever printer Auto-detect picks (in *Windows printer driver* mode, any non-virtual printer). The **Note** row also says when no receipt printer was found. Check it if receipts come out in the wrong place. Printers 2 and up have no Auto-detect, so one of them that was removed prints nothing and says so.

A printer that Printer Bot holds back, because a job it sent does not leave the print queue, shows the reason in its card and fails its receipts at once. See *Printers that do not take ESC/POS*.

## How receipts look, and theme.css

Receipts use one typeface (Segoe UI) in two weights: bold for titles, names and amounts, regular for everything else. Only High Roller messages can use italics. Everything is black on white. A black Twitch, YouTube or Kick logo sits at the bottom where the platform has one, followed by a short date in your computer's language and 12/24-hour style. The profile picture is at the top, 59 mm wide on 80 mm paper and 46 mm wide on 58 mm paper. It is larger than in earlier versions (49 mm and 41 mm), and the receipt is not longer for it: the spaces around the picture, the lines and the logo are a little smaller.

To change the look, put CSS in `theme.css` in the data folder (**Advanced → Customize receipts** in the dock shows the folder, relative to your Streamer.bot folder, and has a **Copy folder path** button). It applies on the next print with no restart. For example:

```css
#receipt-icon { height: 2em; }       /* smaller platform logo */
#receipt-icon { display: none; }     /* no platform logo */
#receipt-avatar { display: none; }   /* no profile picture, which leaves no margin above the first line. Add #receipt-container { padding-top: 16px; } for one */
```

To change the size of the picture, set `--pb-avatar` (the width on 80 mm paper, `13.875em` is the default) and `--pb-avatar-bleed` (how far the picture may go into the side margins of 58 mm paper, `10px` is the default), for example `#receipt-container { --pb-avatar: 12.5em; --pb-avatar-bleed: 5px; }` for a smaller picture. A picture that is larger than the old size takes its extra height out of the spaces around it, as far as they go, so the receipt keeps its length. A smaller picture makes the receipt shorter.

You can style `#receipt-container`, `#receipt-avatar`, `#receipt-title` (with `.big` for amounts), `#receipt-subtitle`, `#receipt-content` (its blocks have class `.part`), `#receipt-icon` and `#receipt-date`. A receipt without a picture has `.no-avatar` on `#receipt-container`. On 80 mm paper the receipt page is 272 pixels wide (181 on 58 mm paper).

**Avoid `vh` units, `height: 100%` and `min-height: 100vh`.** The receipt is laid out in a window that is always 5,000 pixels tall, so those make every receipt about 1.3 m long.

## Where Printer Bot keeps its files

The first time it runs, Printer Bot creates its own data folder, `<Streamer.bot>\SassyTP\printer-bot\` (`<Streamer.bot>` is your Streamer.bot folder), and keeps what it writes there. Two things sit outside that folder: the profile of the hidden Edge and the automatic copy of your settings (see below and *Backing up your settings*).

| File or folder | What it is |
|---|---|
| `settings.json` | your settings (made by Printer Bot, changed from the dock or by hand) |
| `theme.css` | optional, yours: restyles receipts |
| `receipts\` | the pictures saved in *Preview only* mode (those of printers 2 and up end in `_p2`, `_p3` and so on) |
| `avatars.json` | remembered profile-picture addresses (viewer names and picture addresses), and the names a lookup could not find, kept for two hours. **Advanced → Clear picture cache** empties it |
| `printer-checks.json` | your answers to **Check this printer**: the name of the print queue, its driver and yes or no. Delete the file to forget them |
| `renderer.html`, `renderer.html.sig` | a downloaded receipt layout and its signature, once verified and used |
| `renderer.rejected` | the number of a downloaded layout that did not start |
| `core\api1\` | program updates and the updater's notes: a folder for the downloaded version that runs and one for the version before it. Small files record which version runs, which came before, which versions you went back from and how often a version was running when Streamer.bot ended before it had settled in. Its `backup\` folder keeps the last three copies of `settings.json`, made before a new version starts for the first time. |
| `settings.json.bad` | a copy of an unreadable `settings.json` (Printer Bot then puts the backup copy back, or uses the defaults when there is none) |
| `%LOCALAPPDATA%\SassyTP\printer-bot\mirror\` | the automatic copy of `settings.json` and `theme.css` (see *Backing up your settings*), with `mirror.txt` |
| `last_event.json`, `last_receipt.png` | only with **Keep debug files** on (they contain viewer names and messages) |

The hidden Edge keeps its own profile in `%LOCALAPPDATA%\SassyTP\printer-bot\edge-cdp-profile-v5` (from 3.0.5; the folders `edge-cdp-profile-v4...` of earlier versions are no longer used and can be deleted while Streamer.bot is closed), and the backup copy of your settings sits in the folder `mirror` next to it. The browsers after the first (see *Receipt browsers* above) keep their profiles in folders of the same name with `-b1`, `-b2` and so on added, and listen on this PC only, on the ports 9292 to 9306. Printer Bot does not delete a profile folder when it closes a browser. Before a browser starts, Printer Bot sets its profile so that Edge never tries to sign in to your Windows account (a try with an empty password counts as a failed sign-in) and never signs in to the Microsoft account of Windows (3.0.5). An Edge process with no window in Task Manager is one of Printer Bot's receipt browsers. They may outlive Streamer.bot and are safe to end. Printer Bot starts a new one when needed.
