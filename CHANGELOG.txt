Printer Bot changelog

Every release of the Printer Bot action gets an entry here, newest first. The version number is the one of
the action you import into Streamer.bot. The dock in OBS follows it, so you do not have to track the dock's
own version.


2.3.0 (2026-10-05)

New
- Gift sub receipts have no length limit. A gift bomb prints every recipient name that Twitch or Kick sends,
  whether that is 50, 500 or 5,000. The old limit was 200 names. Long lists take a moment to draw and use a
  lot of paper (500 names are about 3 meters).
- New dock setting "High Roller: maximum length" (Advanced). It is the longest a High Roller message can
  print, in inches, up to 40. It has the last word over "bits per inch", it applies to cheers only and
  it never shortens a gift sub list or any other receipt. 0 keeps the built-in limit of about 16.7 inches.
- New Test print sample, TwitchGiftBombBig, with 500 recipients. Use it to see that a long list prints in
  full.

The dock
- The dock now matches your Printer Bot version. The address you put in OBS opens a small launcher. It asks
  the action which version it is and shows the dock made for that version. A new dock can no longer break
  an action that was not updated. Printer Bot 2.2.1 and older keep the exact dock they had.
- Reloading the dock picks up a new dock version even when OBS holds on to old files. The addresses of the
  dock's files carry a stamp that changes with the file, and the launcher asks for its list of versions
  fresh every time. Caching stays on for files that did not change.
- The dock shows a note when its page is older than the action, and asks you to reload it.
- When you give the dock your Streamer.bot password for the first time, it now shows its status at once. The old dock needed a reload for that.
- A receipt that is too tall for the preview shows a short sentence where the picture would be.

Other changes
- Very tall receipts are photographed in parts and joined before they print. The Windows printer driver
  mode prints them in bands. Normal receipts print exactly as before.
- The action follows the dock to another folder on the same web host when it asks for renderer updates, so
  a new dock version in its own folder keeps getting layout updates.
- The status the action sends names the oldest dock page it works with.
