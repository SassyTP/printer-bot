# Privacy

This guide covers what stays on your PC, which services Printer Bot contacts and how Printer Bot is protected. [SECURITY.md](SECURITY.md) covers reporting a vulnerability, and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) lists third-party material and the exact hosts.

## Privacy and third-party services

Printer Bot has no telemetry or analytics. Your settings (including the printers you added and their rules, which can hold viewer names and words you typed), a copy of `settings.json` and `theme.css` in `%LOCALAPPDATA%\SassyTP\printer-bot\mirror`, `avatars.json`, `printer-checks.json` (the names of print queues and their drivers, with your answers to **Check this printer**), the files that **Save settings** writes into the folder `backups` (from 3.0.3; they hold what `settings.json` holds) and, with **Keep debug files** on, `last_event.json` and `last_receipt.png` stay on your PC. The copy holds what `settings.json` holds and is never sent anywhere. The dock keeps a few choices of its own (such as Follow the rules) in the storage of the browser it runs in, and from 3.0.4 the values you type for a test print; they stay in that browser and **Reset to the sample** removes them. Deleting the folder removes it. The action and the dock in this repository send no settings, receipts or usage data to the dock's host or anyone else. Drawing a receipt uses a few public services:

- **decapi.me** (Twitch) and **kick.com** (Kick) receive a viewer's login name to look up the address of their profile picture. Printer Bot remembers the address in `avatars.json`. It remembers a name these services do not know for two hours, so it asks about that name once in that time. Donor and buyer names on StreamElements, Streamlabs and Fourthwall are looked up as Twitch names when they use only letters, digits and underscores (up to 25 characters). No setting switches these lookups off. Test prints of Twitch or Kick samples look up the public profile picture of SassyTP.
- **Image hosts** (Twitch, Kick, YouTube and Google profile pictures, BetterTTV, 7TV, FrankerFaceZ) see an image request from your PC when they serve profile pictures and emotes. The page asks for a larger copy of a profile picture from the same host first, and uses the smaller one if the larger one is not there. No other host is contacted. The exact list is in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
- **Image sites** (Imgur, Catbox and ImgBB) see a picture request from your PC when a High Roller message holds a link to a picture on that site and the message prints (no other message has pictures). A site is contacted only while you have it switched on under **Images in messages** (in the **Advanced** card of the dock), and none is on by default. The request is one plain GET for the address of the picture (https, without the query), sent from the hidden Edge with no cookie, no login and no referrer, so the site sees your PC's internet address and the Edge version, like any web page, and that the picture was asked for. Printer Bot does not look at what a picture shows and keeps no copy: Edge holds the picture in memory and in its own cache folder only until the quiet gap 1.5 seconds after the receipt, when Printer Bot empties the browser's cache. From 3.0.11, for the link of an Imgur album (`imgur.com/a/<id>`, `imgur.com/gallery/<id>`) in such a message, the action itself (not the hidden Edge) first asks **imgur.com** which picture of the album comes first: one GET for the album's list of pictures and, only if that gives no answer, one for the album's page. The request holds the album's id from the link and nothing else of the message, with no cookie, no login and no referrer and the user agent `PrinterBot/<version>`, so Imgur sees your PC's internet address and which album was asked for. The answer is kept in memory for ten minutes and is not written to disk. From 3.1.0 the same is done for a Catbox album (one GET for the album's page at **catbox.moe**) and for an ImgBB album or ImgBB viewer link (one GET for the album's page, with the sort of the link, or the picture's page at **ibb.co**), with the same limits: the id from the link and nothing else of the message, no cookie, no login, no referrer. A site you left off is never contacted, and no address of a link is sent anywhere else.
- **A Brother VC-500W sticker printer** (from 3.2.0) is a device on your own network. While a printer of the dock is a VC-500W on Wi-Fi, Printer Bot connects to it at the address you gave (its name, looked up with your PC's own name lookup, or its IP address; port 9100), sends it the picture of each receipt for it, and reads its state (asleep, busy, the tape left, the cassette) every minute. The address must be on your own network, so nothing of this leaves it. Over USB the picture goes to the printer's Windows print queue, as a receipt for a thermal printer does. The printer keeps nothing Printer Bot knows of; what it does with a picture it prints is the printer's own.
- **The U.S. Treasury** (`api.fiscaldata.treasury.gov`, from 3.0.2) sees a request from your PC for its exchange rates, only while the **YouTube High Roller threshold (amount)** is above 0 and a printer has **Allow YouTube High Roller prints** on or (from 3.0.5) prints on Letter paper with **Large message**, at most every 12 hours (every 15 minutes after a failure). The request asks for the rates of the last six months and carries nothing of you or your viewers: no name, no amount, no setting, only the date in the address and the user agent `PrinterBot/<version>`. The Treasury sees your PC's internet address, like any web site. Printer Bot keeps the rates in `exchange-rates.json` in its data folder. With the switch off on every printer and no printer on Large message, it is never contacted.
- **The dock's web host** is the author's Cloudflare site for the hosted dock and your own server for a dock you host. It sees requests for the dock files and for update checks. The layout check asks for a version file, then the layout and signature if something newer exists. Those requests say they come from Printer Bot and which version, and the host sees your internet address. The author's Cloudflare site counts requests to the hosted dock and may log the path, the status, the country and the first part of the user agent. The dock in this repository sends the host nothing about your Streamer.bot address, port or password. Those stay in your browser. A modified dock could send them (see [Trust](DOCK_SELECTION.md#trust)).
- **The program update check** also goes to the dock's web host. It asks for two small files, `core/api1/manifest.json` and its signature `core/api1/manifest.json.sig`, which together are a signed list that names the newest program. The program itself, `core/api1/core-<version>.bin`, is requested when you press Update or when an automatic install starts, and both ask for the two small files once more first. The check runs at the times listed in [Updating](UPDATING.md#update-from-the-dock). It asks for nothing while **Download updates** is off or no update source is stored. With **Try prerelease versions** on, it also asks for `core/api1/prerelease/manifest.json` and its signature, and for the library of a prerelease from the same folder when you install one. With the option off it asks for nothing in that folder. Each request names itself `PrinterBot/<version> (updater 1.<revision>)` and carries a number that is your PC's current time, which stops a cache from answering with an old file. It carries no cookies, settings or names. The host sees your internet address and the version you run. The author's Cloudflare site may log the first part of the user agent, so it can count how many installs run each version while an update rolls out.

The dock page keeps a few things in your browser for its web address, and they stay there: the Streamer.bot address and port, the password when **Remember on this computer** is ticked, whether the Advanced, Updates and Test cards are open, which printer cards you opened (by number, under the key `pbPrinterCards`), whether **Follow the rules** is switched on in the Test card (under the key `pbTestFollowRules`) and whether you dismissed the note about restored settings (under the key `pbMirrorNote-<version of the dock page>`). The launcher page keeps the last Printer Bot version it saw and the bars you hid. None of it holds a viewer name, and the dock sends none of it to the dock's web host.

## How it is protected

- The receipt page runs under a strict policy, and the hidden Edge can look up only the few web hosts listed in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Every other name fails to resolve, so even a taken-over receipt page cannot reach other programs on your PC or home network.
- Printer Bot uses a downloaded layout only if it carries the author's signature, is newer than the current one and starts. The signature proves who published the layout. You trust the author for what the layout does.
- Printer Bot uses a program update only if all of this holds. The author signed it with a code key built into your import. The downloaded file matches the signed list byte for byte. The update is newer than the running program and at least as new as any update you installed before. It starts. Printer Bot checks a stored update again at every start. An update that fails a check is skipped and the running version stays, the built-in one if need be. The signature proves who published an update. It does not cover the dock's code or the import text, and you trust the author for what an update does. If the code key is ever stolen, the author has a second key, kept apart, that can revoke it (see [SECURITY.md](SECURITY.md)).
- The dock's commands over Streamer.bot's WebSocket are limited to a short list. It can change the settings in [The dock's settings](PRINTER_OPERATION.md#the-docks-settings) (the printers and rules among them), request sample prints from a fixed list (at most 20 a minute), ask where an event with values it names would print (the answer is a list of printer numbers), send one short test line to a printer after you press **Check this printer**, take the jobs Printer Bot sent, or after two clicks every job, out of a print queue and read the status and last receipt. It can check for or reset the layout, set where updates come from and make Printer Bot forget the remembered viewer pictures. It can ask for a program update check, install the newest signed update, or go back to the previous or built-in version. None of these commands carries an address, a file or a program. The update source can be set freely the first time. After that it changes only on the dock's "Use this dock" request, and the action cannot tell that request from anyone else's.
- Anyone who can reach an unprotected Streamer.bot WebSocket can use that same channel. They can waste paper, send receipts to *Preview only*, switch update checks off, switch automatic installs on, switch prerelease versions on, start a program update, go back to an earlier version, change where updates come from, make Printer Bot look every viewer's picture up again, switch the Hype Train receipts on or off, change the Hype Train end wait, send one short test line to a printer and change which printers print which events. The status they can read also lists your rules. They can also read the status and the last receipt picture, which shows a viewer's name and message. See [Lock the WebSocket server](TROUBLESHOOTING.md#lock-the-websocket-server-recommended).

Three points hold when a dock host, a CDN, a connection in between, a program on your network or a hostile dock page misbehaves:

1. Nothing that reaches Printer Bot through Streamer.bot's WebSocket carries a program or a file. The only address a command can set is the update source, under the rules above, and the author's signature decides what runs from there.
2. Printer Bot runs program code from two places only: the import you pasted, and a program update signed with the code key built into that import and checked as listed above. Receipt layouts are a separate download with their own signature.
3. So none of them can make Printer Bot run a program the author did not sign. They can stop updates, or keep offering an older update that the author signed and that is newer than your running version. A dock page is trusted code of its own (see [Trust](DOCK_SELECTION.md#trust)).

To report a vulnerability, see [SECURITY.md](SECURITY.md).
